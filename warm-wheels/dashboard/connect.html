The Pi token stays in this laptop server's memory. Connecting does not arm or drive the rover. An unreachable Pi never switches to synthetic imagery.

Connect in three steps

  1. Join the same Wi-Fi.

    Put the laptop and Pi on the same router or phone hotspot. Some venue guest networks isolate devices; use your own hotspot if they cannot reach each other.

  2. Start W.A.R.M wheels on the Pi.

    Copy the project to the Pi, prepare its environment, then run:

    bash scripts/start_pi_camera.sh

    This starts camera-only mode and prints the address and token. Use hostname -I on the Pi if you need its IP.

  3. Enter the address and Pi token here.

    The RealSense and Uno stay connected by USB to the Pi. The Pi uses its own power supply; the laptop only needs Wi-Fi.

Live driving additionally requires the verified Uno firmware and completed raised-wheel tests. Use START_HARDWARE.cmd for the separate USB-to-laptop bench setup.

PLANNING AREA ≠ PHYSICAL FENCE

What the metre sliders control

The presentation's 1–50 m width and length sliders enforce a boundary in the simulated map. Physical autonomous scanning and a real-world geofence require validated localization and path following, which are not connected in this version. For the live rover, use a marked test area and supervised drive.
